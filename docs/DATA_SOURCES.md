# 데이터 출처와 구성

[프로젝트 소개](../README.md) · [입출력 형식](DATA_FORMAT.md) · [실행 안내](SETUP.md)

PET-I에서 사용한 원본 이미지·라벨, 설명 생성 입력, 검색 근거, 생성 출력의 출처와 형식입니다. 원본 데이터는 AI Hub 공식 안내, 프로젝트 사용 규모는 [최종 보고서](https://github.com/ho72/pet-i-vlm-diagnosis/blob/main/docs/PETI_final_report.pdf)를 참고합니다.

## 1. 전체 프로젝트의 원본 이미지와 라벨

| 항목 | 내용 |
| --- | --- |
| 데이터셋 | AI Hub — 반려동물 안구 질환 데이터 |
| 공식 페이지 | [dataSetSn=562](https://www.aihub.or.kr/aihubdata/data/view.do?currMenu=115&dataSetSn=562&topMenu=100) |
| 구축년도 / 최초 개방 | 2021년 / 2022.07.14 |
| 공식 학습용 데이터 형식 | JPG 이미지와 JSON 라벨 |
| PET-I에서 선별·전처리한 이미지 | 반려견 7개 분류 항목, 5,600장 |
| PET-I 분류 항목 | 무증상·결막염·궤양성각막질환·백내장·안검염·안검내반증·유루증 |

공식 JSON은 `Meta`의 이미지 정보와 `label`의 라벨링 정보로 구성되며, 질환명은 `label_disease_nm`, 질환 정도는 `label_disease_lv_1`~`label_disease_lv_3` 등에 기록됩니다. 이 구조는 AI Hub 원본의 형식입니다. 설명 생성 코드의 `report_json`·`normalized` 형식과 동일하지 않습니다.

프로젝트에서 준비한 원본 이미지는 5,600장입니다. 원본 JPG·라벨 JSON은 이 레포에 포함되어 있지 않으며 AI Hub 공식 제공 절차에 따라 받아야 합니다.

## 2. 이 코드에 들어오는 진단명과 증상

전체 프로젝트에서는 이미지·질환 라벨을 정리하고 증상 텍스트를 준비한 뒤 설명형 데이터를 생성했습니다. 증상 추출과 설명 생성은 서로 다른 단계이며, 이 저장소의 `auto_ctx.py`는 이미 준비된 진단명·증상을 입력받는 단계입니다.

| 입력 값 | 이 모듈의 처리 |
| --- | --- |
| `image_path` | CSV에서 파일명 stem을 식별자로 사용. 이미지 내용을 읽지 않음 |
| `diagnosis` | 준비된 질환명을 전달받음. 새로운 진단을 추론하지 않음 |
| `symptoms` | 준비된 증상 텍스트를 목록으로 정규화 |
| JSON의 `normalized` / `report_json` | 진단명·증상·기존 컨텍스트를 전달하는 프로젝트용 입력 구조 |

공식 원본 라벨을 이 CSV·JSON으로 변환하는 전처리 전체, 이미지별 증상을 추출하는 코드와 전수 매핑 자료는 이 저장소에 포함되어 있지 않습니다.

## 3. 설명에 사용하는 지식 근거

| 근거 | 저장·수집 형식 | 출처를 확인할 수 있는 범위 |
| --- | --- | --- |
| [로컬 corpus](../corpus/) | 질환별 TXT 문서 7개 | 제목·키워드·개요·시각적 단서·정규화 증상 항목 등. 문서별 원문 URL·작성일·생성 방법의 메타데이터는 없음 |
| DuckDuckGo | 검색 결과의 제목·URL·요약 | 실행에서 수집된 결과의 URL을 컨텍스트와 디버그 파일에 저장. 검색된 원문 전체를 수집하는 구현은 아님 |
| Wikipedia | 영문 페이지 제목·URL·본문 앞부분 | 실행 시 페이지를 검색해 본문 발췌를 가져옴 |
| `SEED_KB` | 코드에 저장된 진단별 요약과 URL | Merck Veterinary Manual·VCA·Cornell 등의 URL을 포함하지만 실행 시 해당 원문을 다시 가져오지는 않음 |

로컬 문서는 AI Hub 공식 라벨과 별도로 준비한 프로젝트 자료입니다. 문서별 원문 URL·작성 이력이 저장되어 있지 않아 출처 추적과 재사용을 위해서는 별도 확인이 필요합니다.

현재 로컬 매핑은 `무증상.txt`를 포함한 일곱 분류 항목을 지원합니다. [파이프라인 설명](PIPELINE.md)에 현재 지원 범위와 필터 완화 동작을 기록했습니다.

## 4. 생성 데이터의 성격과 출력

Teacher LLM인 GPT-4o가 진단명·증상·검색 컨텍스트를 받아 한국어 설명문을 생성합니다. 생성문은 AI Hub 원본에서 제공한 정답 설명문이 아니라 **프로젝트에서 생성한 설명형 텍스트**입니다.

설명 생성이 성공하면 입력마다 다음 두 레코드를 같은 JSONL에 저장합니다. 실패는 `error`, 실행 미리보기는 `preview`로 구분합니다.

- `service`: 입력 진단·증상·컨텍스트와 생성 설명문, 간단한 상태 정보.
- `sft`: 위 입력과 근거를 이용해 코드가 구성한 검색·열람 대화 및 최종 설명문.

현재 `sft`에는 이미지 파일·이미지 토큰이 들어 있지 않습니다. 전체 VLM 학습에 사용하려면 해당 이미지와 연결하고 학습기의 형식에 맞게 전처리해야 합니다. 형식과 필드는 [데이터 형식 문서](DATA_FORMAT.md)를 참고하세요.

## 6. 출처 추적이 가능한 범위

생성 JSONL에는 `text_name`, 진단명·증상, 컨텍스트의 번호·제목·URL·발췌와 검색어가 기록됩니다. 이를 통해 외부 URL이 있는 컨텍스트는 출처를 확인할 수 있습니다. URL이 없는 로컬 문서의 원문 출처나 이미지 원본 매핑까지 자동으로 복원할 수는 없습니다.

현재 출력에는 모든 소스의 라이선스·수집 시각·원문 버전이나 Teacher 모델의 상세 버전이 개별 레코드 메타데이터로 저장되어 있지 않습니다.
