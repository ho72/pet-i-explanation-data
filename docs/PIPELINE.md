# 파이프라인 설계와 현재 한계

[프로젝트 소개](../README.md) · [실행 안내](SETUP.md) · [데이터 형식](DATA_FORMAT.md)

## 어떤 문제를 다루는가

PET-I에서 이미지 분류 결과만으로는 보호자에게 설명할 텍스트가 충분하지 않았습니다. 이 모듈은 준비된 진단명·증상과 질환별 문서를 연결하여 설명형 학습 데이터를 만드는 흐름을 구현합니다. 전체 VLM 학습 코드·챗봇 서비스·실시간 진단 서버를 모두 포함한 저장소는 아닙니다.

## 함수별 구현

모든 함수는 [auto_ctx.py](../auto_ctx.py)에 있습니다.

| 함수 | 역할 |
| --- | --- |
| `load_rows_from_csv`, `load_rows_from_json_dir` | CSV·JSON 입력을 공통 레코드로 정규화 |
| `load_local_corpus_by_diag` | 파일명에 진단명이 포함된 로컬 `.txt` 문서를 매핑 |
| `ddg_search` | 진단별 영어 별칭으로 검색하고 결과의 제목·URL·요약 수집 |
| `wiki_chunks` | 영문 Wikipedia 페이지 본문 앞부분을 가져옴 |
| `filter_docs`, `prefer_authority`, `dedup_near_duplicates` | 문서 길이·선호 출처 점수·URL/제목 중복 기준으로 선별 |
| `build_ctx_for_row` | 입력 컨텍스트·로컬 문서·선택적 외부 검색을 조합하고 근거 번호 부여 |
| `compose_teacher_prompt`, `call_teacher_llm` | 네 섹션의 한국어 설명을 요청하는 프롬프트와 OpenAI 호출 |
| `create_sft_messages` | 문서 수집 결과와 생성문으로 검색·열람 대화를 구성 |
| `process_rows` | JSONL 저장, 상태 정보 기록, 행별 예외 처리 |

## 컨텍스트 선별 방식

1. 입력 `ctx`와 해당 진단의 로컬 문서를 모읍니다.
2. 옵션을 지정하면 DuckDuckGo 검색 요약과 영문 Wikipedia 본문을 추가합니다.
3. URL을 가진 문서가 하나도 없으면 진단별 저장된 시드 문서 하나를 보강합니다.
4. 최소 120자 길이·광고 링크 필터를 적용합니다.
5. 선호 도메인 URL에 5점, DuckDuckGo·Wikipedia 출처에 각각 1점, 제목에 `dog`가 포함되면 1점을 부여합니다.
6. 동일 URL 또는 제목 앞부분 기준으로 중복을 제거하고 상위 `k`개에 번호를 부여합니다.

필터 이후 문서가 `max(4, k//2)`보다 적으면, 현재 코드는 **로컬 문서·시드만으로 컨텍스트를 다시 만들고** 최소 길이를 60자로 완화합니다. 이 과정에서 이미 수집한 웹 결과나 입력 컨텍스트가 최종 결과에서 빠질 수 있습니다. 로그의 `ddg/wiki retry` 표현과 달리 이 완화 분기에서 외부 검색을 다시 호출하지는 않습니다.

시드 문서는 코드에 저장된 텍스트와 URL입니다. 실행할 때 URL 원문을 새로 가져오는 방식이 아니므로 최신 내용과의 일치 여부는 별도로 확인해야 합니다.

## 설명 생성과 학습 대화의 관계

Teacher에는 번호가 붙은 컨텍스트와 진단명·증상을 사용자 프롬프트 한 개로 전달합니다. 현재 CLI에서는 `gpt-4o`, temperature `0.7`, timeout `60`초를 사용합니다. 섹션·한국어 말투·인용 표기 등의 요구사항은 프롬프트 지시입니다.

검색·열람 대화는 Teacher의 실제 에이전트 실행이 아니라 `create_sft_messages`가 구성합니다. 외부 검색을 끈 경우에도 진단별 별칭으로 `search` 메시지가 만들어질 수 있습니다. 출력 형식만으로 실제 검색 수행을 판단하지 마세요.

## 재현과 해석의 한계

| 항목 | 현재 상태 |
| --- | --- |
| 입력 이미지 | 읽거나 분석하지 않음. `image_path`에서 식별자만 추출 |
| 질환별 로컬 매핑 | 결막염·궤양성각막질환·백내장·안검염·안검내반증·유루증의 여섯 이름 기준 |
| 무증상 문서 | 파일은 있으나 현재 진단 목록에 없어 로컬 매핑에서 제외됨 |
| 컨텍스트 근거 제한 | 프롬프트 안에 전문 지식 부연 허용과 CTX 외 내용 금지 지시가 함께 존재. 엄격한 근거 준수는 검증하지 않음 |
| 입력의 지시 옵션 | `freeze_report`는 별도 실행 제어에 사용하지 않고, `use_ctx_only`도 프롬프트 분기를 바꾸지 않음 |
| 품질 확인 | 입력·컨텍스트·출력 길이에 대한 간단한 상태 기록. 인용 정확성·사실성·질환 설명의 타당성 검증 아님 |
| LLM 폴백 | 실제 규칙 기반 보고서 생성 대신 `오류 - 풀백` 문자열 반환 |
| 검색 재현 | 웹 검색 결과는 시점·서비스 상태에 따라 달라짐. 패키지 lock·검색 품질의 정량 평가 없음 |
| SFT 호환성 | 자체 메시지 형식. 학습기별 전처리·필터·도구 스키마 변환 필요 |

## 이번 정리에서 변경한 코드

API 키 자리표시자 `<YOUT_API_KEY>`가 따옴표 없이 들어 있어 Python이 파일을 파싱하지 못했습니다. 주석으로 남아 있던 환경변수 방식인 `os.getenv(api_key_env, "")`를 복원했습니다. 헤더의 옛 파일명도 실제 `auto_ctx.py`로 맞췄습니다.

검색 순위, 프롬프트, 폴백 출력, 품질 기록 방식은 현재 코드의 동작을 설명했습니다. 설명 생성이나 검색 품질을 새로 측정한 성과는 없습니다. 기존 생성 예시는 [별도 문서](GENERATED_EXAMPLES.md)에 보존했습니다.
